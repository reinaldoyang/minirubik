# IDDFS and IDA* experiment

The original `solver.c` remains the exhaustive BFS correctness oracle. The two
experimental solvers share `cube/cube.c`, use move order
`R R2 R' B B2 B' D D2 D'`, and prune a move when its face equals the preceding
move's face. That pruning does not remove an optimal HTM solution because
adjacent turns of one face can be combined into one HTM move or cancelled.

The repository separates the reusable cube model under `cube/`, search
algorithms and timing under `search/`, executable frontends under `apps/`,
correctness checks under `tests/`, and measurement scripts under `benchmarks/`.

`solver_iddfs` tries depth limits from zero upward. `solver_idastar` tries
increasing `g + h` thresholds, where `h` is the maximum of two exact abstract
distances. Both searches use fixed arrays as explicit DFS stacks.

## Counter definitions

- `solution_length`: number of HTM moves returned.
- `nodes_expanded`: non-goal nodes whose legal outgoing moves are examined;
  nodes rejected by a depth or `f` bound are not expanded.
- `children_generated`: legal children actually constructed after same-face
  pruning, including children later rejected by a bound.
- `search_iterations`: depth limits attempted by IDDFS or `f` thresholds
  attempted by IDA*.
- `maximum_stack_depth`: greatest search depth reached, with the root at zero.
- `pdb_lookups`: individual PDB array reads used by heuristic evaluations.
  IDDFS performs none; one IDA* heuristic evaluation performs two.
- `host_seconds`: monotonic wall time from solver entry through completion,
  stored as integer nanoseconds and rendered in seconds. IDA* table generation
  is a separate host build step and is therefore outside this measurement.
- `static_table_bytes`: persistent PDB and rank-transition payload, excluding
  search stacks. It is zero for IDDFS and 40,383 bytes for IDA*: 5,769 PDB
  bytes plus 34,614 bytes for three permutation and orientation quarter-turn
  tables.

Counters accumulate over all search iterations. Host table generation does not
count as search-node expansion or as heuristic lookup.

## Pattern databases

The permutation PDB contains one byte for each of the 5,040 corner
permutations. The orientation PDB contains one byte for each of the 729 legal
orientation vectors. Each is generated by BFS from abstract rank zero with all
nine HTM moves, so every entry is an exact shortest distance in its abstraction.
Projecting a full move into either abstraction cannot increase distance, and
the maximum of the two lower bounds is admissible.

`make regen-idastar-tables` runs the host generator and rewrites the checked-in
constant PDB and quarter-turn tables. The target search stores only the two
abstract ranks in each stack frame. It applies an HTM move with one to three
table lookups and does no ranking, unranking, multiplication, division, or
modulo in its search loop.

## Commands

```sh
make solver solver_iddfs solver_idastar
make check-search
make benchmark-search > measurements.csv
```

`check-search` compares all three requested cases with the original BFS
solver, applies every returned solution, and checks PDB admissibility against
an exhaustive exact-distance BFS for all 3,674,160 states. The benchmark target
prints measurements; it does not store or claim precomputed results.

## RV32I reference build

`make rv32i` produces `solver_idastar_rv32i.elf` and its disassembly without
linking the host CLI, timer, or C library. The freestanding harness uses the
distance-11 state `21345671111111`, stores its solution and counters in exported
`target_*` symbols, and exits through Ripes environment call 10. Use
`make check-rv32i` to reject RV32M multiply/divide instructions and
`make rv32i-info` to display the ELF header and section sizes.

`make rv32i-asm` builds the self-contained `target/solver_idastar_all.S`, which
contains the startup, target harness, storage, and search instructions directly.
The three split assembly files are retained as readable reference copies but
are not build dependencies. The public search routine accepts permutation and
orientation ranks, uses an explicit 8-byte-frame stack, and keeps hot counters
in registers. The default harness passes ranks 720 and 0 for
`21345671111111`. It links the generated table source only for constant data;
no compiler-generated C function is present in the assembly ELF. Use
`make check-rv32i-asm` and `make rv32i-asm-info` for its ISA and size checks.

`make rv32i-asm-cases` builds three separately named ELFs without editing the
assembly source: `solver_idastar_asm_solved.elf` uses ranks `(0, 0)`,
`solver_idastar_asm_short.elf` uses `(1104, 426)`, and
`solver_idastar_asm_distance11.elf` uses `(720, 0)`. Their expected optimal
solution lengths are 0, 1, and 11 respectively.
